# Reporting Workflow

This workflow keeps ArbiterSTG reports focused on classification rather than judgment.

## 1. Identify Residue

Name the residue and state the execution context.

Do not infer meaning from residue presence.

## 2. Classify Accessibility

Record whether the residue is directly accessible, partially accessible, proxy-mediated, bridge-dependent, unreachable, destroyed, or structurally unrecoverable.

Do not infer non-execution from access failure.

## 3. Determine Trace Eligibility

Apply the Trace Eligibility Threshold. If the threshold is not met, record Null, Shadow, or outside-formal-review status as appropriate.

## 4. Assign Mode

Assign one or more trace modes:

- Admission
- Limited Admission
- Masking
- Routing
- Shadow
- Transfer
- Null

## 5. Record Constraints

Name limitations, bridge dependencies, proxy dependencies, inaccessible regions, route changes, and possible collapse risks.

## 6. Attach Warnings

Attach Authority Laundering flags or Collapse-by-Clarification warnings when relevant.

## 7. Record Indices

Record `RLCI` and `RAI` scores where useful.

## 8. State Claim Limits

End with a clear statement of what the trace does not establish.
